# Финальные результаты - AutobahnCV Occluded Plate Detector

## Финальное решение по релизу

**Решение: MVP готов; production-релиз возможен только с ограничениями.**

Проект достиг состояния MVP: основной пользовательский сценарий реализован,
API и frontend готовы, ML pipeline интегрирован, а вокруг MVP подготовлена
инфраструктура. Система может принимать изображения автомобилей, находить
автомобиль и область номерного знака, запускать OCR, строить embedding,
искать похожие автомобили в Elasticsearch и возвращать пользователю список
наиболее вероятных кандидатов.

При этом систему пока нельзя считать полностью автономным production-решением.
Она готова для демонстрации, контролируемого тестирования и дальнейшего сбора
данных, но финальная идентификация автомобиля должна подтверждаться
человеком-оператором.

## Почему было принято такое решение?

Такое решение принято потому, что основная продуктовая идея уже реализована,
но часть важных quality gates еще не закрыта полностью.

Ценность MVP уже есть: проект объединяет распознавание номерного знака и поиск
по визуальному сходству автомобиля. Это правильный подход для бизнес-задачи,
потому что скрытые или частично видимые номера не всегда можно надежно
обработать только с помощью OCR. Использование одновременно видимого фрагмента
номера и embedding автомобиля дает оператору ранжированный список вероятных
кандидатов, а не один хрупкий ответ.

В то же время релиз должен быть ограниченным, потому что основные оставшиеся
риски связаны с качеством моделей и доказательствами их качества:

- OCR нужно улучшить для более надежного распознавания российских номеров в
  сложных случаях.
- Система пока не заменяет скрытые символы номера на `*` автоматически;
  пользователь может вручную передать запрос вида `A8**AA977`, но
  автоматическая occlusion-aware логика еще не завершена.
- Обработка фотографий с закрытыми или замазанными частями номера все еще
  слишком зависит от ручного ввода, потому что OCR пока недостаточно стабильно
  извлекает видимую часть номера.
- Финальные validation metrics и model artifacts не полностью задокументированы
  в репозитории в соответствии с Definition of Done.

Поэтому корректное решение - не "production ready без ограничений", а
**MVP ready / release approved with limitations**.

## Что еще не готово?

1. **Качество OCR пока недостаточно для полноценного production.**

   OCR модель должна надежнее распознавать российские номера в реальных
   условиях: blur, грязь, плохой угол, слабое освещение, частичная видимость и
   перекрытие. Текущий post-processing помогает, но он не заменяет более сильную
   OCR модель, обученную и проверенную на репрезентативных данных.

2. **Автоматическая маскировка скрытых символов еще не завершена.**

   Желаемое поведение: если часть номера закрыта, система должна определить
   закрытую область и вернуть номер с маской, например `A8**AA977`, а не
   пытаться угадать скрытые символы. Сейчас wildcard-запросы поддерживаются при
   ручном вводе, но pipeline пока не генерирует такие маски надежно и
   автоматически.

3. **Обработка фотографий с закрытыми/замазанными номерами требует доработки.**

   Фотографии, где номер закрыт патчем, предметом или замазанной областью,
   должны обрабатываться без обязательного ручного ввода видимого фрагмента
   номера. Для этого нужны более точная локализация номера, detection закрытой
   области и OCR, который умеет разделять читаемые и нечитаемые зоны номера.

4. **Model artifacts и validation evidence неполные.**

   DoD ожидает наличие файлов моделей и задокументированных метрик для car
   detector, plate detector, OCR model и embedder. В quality gates уже отмечено,
   что production model weights и целевые validation results не полностью
   представлены в репозитории.

5. **End-to-end validation не полностью автоматизирована.**

   В репозитории есть unit/API/service tests, но финальный функциональный набор
   тестов из DoD еще не автоматизирован в CI. Нужны воспроизводимые E2E checks
   на изображениях с полными номерами, частично скрытыми номерами и сложными
   кейсами.

6. **Production rollback и model governance требуют большего подтверждения.**

   MLflow и monitoring infrastructure подготовлены, но проекту еще нужен более
   строгий release process для promotion моделей, rollback и воспроизводимого
   сравнения разных версий моделей.

## Какие есть ограничения?

- Система работает со статичными изображениями, а не с real-time video stream.
- Целевой домен - российские номерные знаки поддерживаемого формата.
- Система не гарантирует 100% точность идентификации.
- Финальное юридически значимое действие не должно выполняться автоматически;
  результат должен подтверждать человек-оператор.
- Low-confidence результаты нужно рассматривать как кандидатов для ручной
  проверки, а не как финальный ответ.
- Полностью нечитаемые номера нельзя восстановить только с помощью OCR; система
  может использовать визуальное сходство и доступные metadata, чтобы предложить
  вероятных кандидатов.
- Скрытые символы номера пока не конвертируются автоматически в `*` надежным
  occlusion-aware OCR pipeline.
- Production inference зависит от наличия реальных обученных model weights в
  ожидаемых путях.
- Текущих validation evidence недостаточно, чтобы утверждать, что все целевые
  ML metrics из DoD достигнуты.

## Что нужно сделать дальше?

1. **Улучшить OCR модель.**

   Дообучить или заново обучить OCR на российских номерах с реалистичными
   искажениями: occlusion, blur, угол камеры, грязные номера, тени, compression
   artifacts и ночные изображения. Нужно фиксировать accuracy, character error
   rate и full-plate accuracy на постоянном validation set.

2. **Добавить occlusion-aware plate parsing.**

   Расширить обработку номера так, чтобы система определяла нечитаемые или
   закрытые области и возвращала masked characters, например `*`. Целевое
   поведение - автоматически генерировать запросы вида `A8**AA977`, когда
   середина номера скрыта.

3. **Улучшить обработку patched photos.**

   Добавить отдельный validation set для закрытых или замазанных номеров и
   тестировать на нем весь pipeline. Цель - уменьшить необходимость ручного
   `plate_query` и научить систему извлекать видимый фрагмент прямо из
   изображения.

4. **Опубликовать model artifacts и validation reports.**

   Сохранить финальные веса моделей, дать ссылки на них в документации и
   добавить компактный отчет с detector mAP, OCR accuracy, embedding top-5
   accuracy, latency и примерами ошибок.

5. **Автоматизировать E2E quality gates.**

   Добавить CI checks, которые запускают полный pipeline на небольшом
   фиксированном наборе изображений и проверяют top-5 behavior, confidence
   thresholds и fallback behavior.

6. **Включить coverage enforcement и type checks.**

   Добавить проверку test coverage в CI и включить mypy или другой type-checking
   step для backend. Это усилит software quality gates и упростит подтверждение
   качества.

7. **Усилить release governance.**

   Описать процесс продвижения модели: candidate model, offline validation,
   shadow/staging check, production promotion, monitoring window и rollback
   procedure. Проверить `HW/ROLLBACK_RUNBOOK.md` на staging и добавить
   конкретные ссылки на MLflow runs / Docker images для production.

8. **Использовать feedback data для retraining.**

   Превратить исправления операторов из feedback endpoint в размеченные примеры
   для будущего улучшения OCR, detector и ranking.

## Итоги

AutobahnCV имеет рабочий MVP и сильную инженерную среду вокруг него: API,
frontend, container stack, monitoring, logging, documentation и feedback
collection уже на месте. Основная оставшаяся работа - качество ML и доказуемость
релиза. Следующая итерация должна быть сфокусирована на улучшении OCR,
автоматической маскировке `*` для скрытых символов номера, обработке patched
photos, публикации model metrics и автоматизированной end-to-end validation.
